# AEMET (Espanha) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Import AEMET warnings (CAP) and station data into fogosapi and serve them on `v2/warnings/aemet*` and `v2/weather/aemet/*`, response-for-response identical to the IPMA endpoints.

**Architecture:** An `AemetTool` does the two-step OpenData fetch. The CAP tar is parsed into `CapMessage` objects and converted into items in the exact IPMA feed format. Those items go through the *same* reconciliation engine and event recorder as IPMA, extracted from `HandleWeatherWarnings` and parameterized by model class. Station data is normalized at write time to IPMA field names and units, so the AEMET controller reuses the IPMA response code.

**Tech Stack:** Laravel 12, PHP 8.3, mongodb/laravel-mongodb 5, Guzzle (MockHandler in tests), PharData, PHPUnit.

**Spec:** `docs/superpowers/specs/2026-11-12-aemet-design.md`. Read it first; this plan only adds the decisions the spec leaves open.

## Global Constraints

- IPMA responses and behaviour must not change. Every existing test passes **unmodified**: never edit a test under `tests/` that exists on `main`.
- No new composer dependencies. Read the tar with `PharData` (the prod image has `phar`).
- The AEMET key lives only in `.env` (`AEMET_API_KEY`) and is read through `config('services.aemet.key')`. Never commit it: tests use the literal `test-key`.
- Every AEMET job is a no-op when `config('services.aemet.key')` is empty.
- Jobs implement `ShouldBeUnique` with `$timeout` < 90 (the Redis `retry_after`), as in `ProcessMadeiraEvents`.
- Store times as UTC datetimes. Serve them exactly as the matching IPMA endpoint does.
- Zones with prefix `64`, `65`, `78` or `79` are not peninsular. Stations in provinces `ILLES BALEARS`, `LAS PALMAS`, `STA. CRUZ DE TENERIFE`, `CEUTA` or `MELILLA` are not peninsular. Check the exact `provincia` spellings in the inventory fixture.
- The level map is `amarillo→yellow`, `naranja→orange`, `rojo→red`. `verde` is never a warning.
- Commits look like `feat(aemet): … (#102)` and end with the `Co-Authored-By` line from the session.
- Run tests with `$S/phpunit.sh [args]`, where `$S` is the session scratchpad: `/private/tmp/claude-501/-Users-tomahock-Projects-Tomahock-fogosapi/4229a787-411f-4041-9ecb-a9772e7c8dc4/scratchpad`. It needs the `fogostest` network and the `fogostest-mongo` container to be up:

    -e MONGO_INITDB_ROOT_USERNAME=root -e MONGO_INITDB_ROOT_PASSWORD=root mongo:7.0

## Review Focus

1. **A partly broken snapshot.** If the tar has one unreadable or invalid CAP file, treat the whole run as failed. Do not reconcile, so the warnings in force are not "retirado". Test: `a_tar_with_a_broken_file_changes_nothing` (Task 5).
2. **DST and offsets.** An `onset` of `…+01:00` (winter) or `…+02:00` (summer) is stored as the right UTC instant and served in Lisbon local time. Test: `summer_offset_is_converted` (Task 4).
3. **Daily strings.** Handle `"Ip"` → 0.0, `"Acum"` → null, `"-2,3"` → -2.3, `"Varias"` (ignored), `dir` `"99"`/`"88"` → null, and missing keys → null. Test: `daily_strings_are_normalized` (Task 7).
4. **Same-level overlaps inside one snapshot.** The real data has two yellow PR windows on `713201` (P1 = 1 h, P2 = 12 h). A second identical run must record no events at all, so the engine never pairs them crosswise. Test: `a_repeated_snapshot_records_nothing` (Task 5).
5. **An unknown station in observations.** An `idema` that is in the observations but not in the inventory gets a station created from `ubi`/`lat`/`lon`. Test: `observation_of_unknown_station_creates_it` (Task 7).

### Task 4: From CAP messages to IPMA-format items

**Files:**
- Create: `app/Support/Aemet/AemetWarningItems.php`
- Test: `tests/Unit/Support/Aemet/AemetWarningItemsTest.php`

**Interfaces:**
- Consumes: `CapMessage` (Task 2).
- Produces: `AemetWarningItems::fromMessages(CapMessage[] $messages, Carbon $now): object[]`. Each item has these properties:
  - the IPMA ones: `idAreaAviso`, `awarenessTypeName`, `awarenessLevelID`, `startTime` and `endTime` (ISO 8601 strings with offset), `text`, and `reportDate` (= `sent`, ISO with offset);
  - extras: `areaName`, `phenomenon`, `parameter`, `probability`, `identifiers` (string[]), and `en` (array).
- `AemetWarningItems::TYPES` is the type map from the spec table. An unmapped phenomenon falls back to `phenomenonName`.

The rules, in this order:
1. Drop messages whose identifier is in another message's `references`, messages with `msgType === 'Cancel'`, and messages referenced by a Cancel.
2. Drop `verde` messages and messages with `expires < $now`.
3. Make one item per area.
4. Group by `(zone, type, level)`. Merge items whose windows strictly overlap into one item:
   - `startTime` is the earliest start and `endTime` the latest end;
   - `text` and `parameter` are the distinct values in phenomenon-parameter order, joined with `" "` and `"; "` respectively;
   - `identifiers` is the union, sorted;
   - `reportDate` is the latest;
   - the rest comes from the first item in identifier order.

   The output must be deterministic for the same input.
